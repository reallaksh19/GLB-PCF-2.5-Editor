## Bugs Found

### BUG-001 — CRITICAL — Macro commands not registered (FIXED)
**File:** `macro/macro-commands.js` line 280  
**Description:** The early-return guard `if (_commands.size) return;` was placed in the **middle** of `registerBuiltinCommands()`, after 7 commands (POLYLINE, SPLINE_GUIDE, STRETCH, ROTATE, BREAK, DELETE, MOVE) but **before** the essential commands: PIPE, ELBOW, TEE, FLANGE, VALVE, REDUCER, SUPPORT, LABEL, LIST, DIST, INSPECT, VALIDATE.  
**Effect:** All essential commands returned "Unknown command: X" on first use.  
**Fix Applied:** Moved the guard to the top of the function (line 135), before any `register()` calls.  
**Status:** ✅ Fixed

---

### BUG-002 — HIGH — View presets (NE/NW/SE/SW/T/F) and Fit-All do not reframe camera
**File:** Camera/view preset logic (viewer-tab.js or scene-renderer.js)  
**Description:** Clicking any view preset button (NE, NW, SE, SW, T, F) or the Fit-All button (`btn-fit-all-float`) produces no visible change to the camera angle or zoom level, even with a populated scene.  
**Repro:** Create any component → click NE → camera unchanged. Click ⊞ Fit All → camera unchanged.  
**Effect:** Designer cannot navigate to standard engineering views or frame the model.  
**Severity:** High — blocks standard CAD navigation workflow.  
**Status:** ❌ Open

---

### BUG-003 — HIGH — POLYLINE/SPLINE_GUIDE/STRETCH/MOVE/BREAK/DELETE fail with "ROUTE engine not initialized"
**File:** `macro/macro-terminal.js` — `initMacroTerminal()` ctx object  
**Description:** Six commands require `ctx.getRouteEngine()` to function, but the macro terminal's `ctx` object (lines 77–88) does not inject `getRouteEngine`. Affected commands: `POLYLINE`, `SPLINE_GUIDE`, `STRETCH`, `MOVE`, `BREAK`, `DELETE`.  
**Effect:** None of these commands work from the macro terminal. Route geometry editing and polyline creation are inaccessible via macro.  
**Fix:** In `initMacroTerminal()`, pass `getRouteEngine` in the options and add `getRouteEngine` to the `ctx` object.  
**Status:** ❌ Open

---

### BUG-004 — MEDIUM — POLYLINE rejects trailing named parameter PIPELINE=
**File:** `macro/macro-commands.js` — `register('POLYLINE', ...)` handler  
**Description:** The POLYLINE handler maps ALL args to XYZ points (`args.map(arg => parseXYZ(arg, ctx))`) without first filtering out key-value pairs (like `PIPELINE=TEST-POLY`). Calling `POLYLINE 0,0,0 1000,0,0 PIPELINE=MYLINE` throws "Invalid coordinate: PIPELINE=MYLINE".  
**Fix:** Call `parseKV(args)` first, filter out KV args, then map remaining args to XYZ points. Same pattern needed for SPLINE_GUIDE.  
**Status:** ❌ Open

---

### BUG-005 — LOW — Master DB filter does not reduce displayed rows
**File:** Master DB panel UI  
**Description:** Typing text into the filter input (e.g. "ELBOW 50") leaves all 27 rows visible; the filter does not narrow results. The "Last match" footer updates but the table does not filter.  
**Effect:** Large component DB is hard to navigate by search.  
**Status:** ❌ Open

### BUG-006 — INFO — Scroll zoom direction inverted (scroll down = zoom out)
**File:** Scene renderer / OrbitControls config  
**Description:** Scrolling DOWN zooms OUT (model gets smaller). Standard CAD convention (and Three.js OrbitControls default) is scroll up = zoom out. This may be intentional but is non-standard.  
**Effect:** Minor UX friction for users trained on standard CAD tools.  
**Status:** ⚠️ Review — possibly intentional

## Real Model Test

Built a full piping rack with the following components via macro terminal:

```
PIPE 0,0,0 6000,0,0 OD=219.1          # 6m header (pipe-004)
TEE 3000,0,0 6000,0,0 3000,1000,0     # branch tee (tee-001)
PIPE 3000,0,0 3000,3000,0 OD=168.3    # branch pipe (pipe-005)
VALVE 1000,0,0 OD=219.1 TYPE=GATE     # valve-002
VALVE 5000,0,0 OD=219.1 TYPE=GATE     # valve-003
VALVE 3000,1500,0 OD=168.3 TYPE=BALL  # valve-004
FLANGE 0,0,0 OD=219.1 RATING=150      # flange-003
FLANGE 6000,0,0 OD=219.1 RATING=150   # flange-004
SUPPORT 1500,0,-200 KIND=REST          # support-002
SUPPORT 4500,0,-200 KIND=REST          # support-003
SUPPORT 3000,1500,-200 KIND=GUIDE      # support-004
```

**Result:** All 11 components created. VALIDATE returned 0 issues. INSPECT verified correct attributes (MATERIAL=CS, BORE, PIPELINE-REFERENCE). Debug Components table shows all entries. Scene renders pipe + valve + elbow geometry.

## Observations for Designer

1. **No auto-fit on model creation** — every time a component is added via macro, camera does not reframe. Designer must manually scroll to locate new geometry. The Fit-All button does not help (BUG-002).
2. **No snap or grid** — the HUD line-draw tool shows `X=0 Y=0 Z=0` coords but there is no visible canvas grid or snap feedback.
3. **Elbow renders as arc** — the ELBOW component renders as a 2D arc curve rather than a 3D cylinder in the current view, which may be intended for the 2.5D mode.
4. **Support renders as small colored dot** — support symbols are very small in the scene; label (e.g. "S-12") renders but the symbol itself is hard to see.
5. **Flange has no visible 3D geometry** — FLANGE components are created and logged but no mesh appears in the scene for them.
6. **Macro terminal is the primary creation path** — the HUD draw tools require canvas interaction which is much slower than macros; macro terminal is more productive for batch model building.
