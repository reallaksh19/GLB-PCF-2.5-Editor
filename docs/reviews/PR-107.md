## 3. Bugs Found & Fixed by Reviewer

> [!CAUTION]
> The following bugs were missed by the automated test suite (tests only exercised straight-line/simple-circle cases and never exercised bulged polylines or multi-cutter circles). Code reading was required to catch them.

### Bug 1 — Critical: Corrupted Bulge-to-Arc Center (sagitta ≠ center distance)
**Files fixed:** `core/geometry/cad-intersections.js`, `core/commands/cad/edit-commands/explode-join-commands.js`

The bulge-to-arc conversion inside `getEntitySegments()` and the LWPOLYLINE Explode path both used:
```js
const sagitta = (chord / 2) * Math.tan(theta / 4);
const cx = mx + nx * sagitta * dir;
```
`sagitta` is the **arc crown height**, not the **center distance**. The correct formula is:
$$d_\text{center} = \frac{\text{chord} \cdot (1 - b^2)}{4b}$$

For `bulge=1` (semicircle), the wrong code placed the center 1 unit *above* the chord instead of *on* it, producing arcs that don't pass through their own vertices.

**Fix:** Added a canonical `bulgeToArc(p1, p2, bulge)` function (using the correct DXF center formula, same as `dxf-geometry-sampler.js`) and replaced all ad-hoc conversions with calls to it.

### Bug 2 — Data Loss: Block Explode Strips Polyline Bulges
**File fixed:** `core/commands/cad/edit-commands/explode-join-commands.js`

When exploding an `INSERT` block, polyline vertices were transformed with `transformPoint()` which returns only `{x, y, z}`. The `.bulge` property was silently dropped, converting all curved polyline segments to straight lines.

**Fix:** Preserved `v.bulge` after `transformPoint`:
```js
const tp = transformPoint(v, transform, basePoint);
if (v.bulge != null) tp.bulge = v.bulge;
```

### Bug 3 — Logic Error: Multi-Cutter Circle Trim Only Considered First Two Cut Points
**File fixed:** `core/commands/cad/edit-commands/trim-extend-commands.js`

With 3+ cutting intersections, the code only examined `angles[0]` and `angles[1]`, ignoring all other cut points. It produced wrong arcs whenever more than two cutters intersected the circle.

**Fix:** Replaced with a correct N-span loop that checks every consecutive angle pair (including the wrap-around segment) to find which span contains `clickAngle`.

### Bug 4 — Direction Inconsistency: Polyline Offset Flips Per-Segment
**File fixed:** `core/geometry/cad-offset-math.js`

`offsetPolylineVertices` called `offsetLineSegment(v1, v2, distance, sidePoint)` per segment, which re-evaluates the dot product to `sidePoint` each time. For a non-convex polyline, segments on opposite sides of `sidePoint` could evaluate to opposite offset directions, causing the output to self-intersect and fold.

**Fix:** Compute the global side sign (+1 or −1) **once** from the first segment, then apply it consistently to all segments.
